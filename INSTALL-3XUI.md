# Установка панели с 3x-ui — пошаговая инструкция

Эта инструкция для тех, кто никогда не ставил подобное. Просто выполняйте шаги
по порядку: копируйте команды целиком и вставляйте в терминал сервера.

**Что получится в итоге:** веб-панель управления + Telegram-бот, который продаёт
VPN-подписки и сам выдаёт ключи в вашей 3x-ui.

## Что понадобится заранее

| Что | Зачем | Где взять |
|---|---|---|
| Сервер с **Ubuntu 22.04 или новее** (от 2 ГБ памяти) | на нём будет работать панель | любой хостинг VPS |
| Доступ к серверу по SSH (логин `root` и пароль или ключ) | чтобы вводить команды | приходит от хостинга |
| **3x-ui версии 3.0 или новее** | сам VPN | шаг 2 ниже, если ещё не стоит |
| Токен бота | чтобы бот работал | Telegram → [@BotFather](https://t.me/BotFather) → `/newbot` |
| Домен (необязательно) | адрес с HTTPS вместо IP | у любого регистратора доменов |

> Панель и 3x-ui можно поставить **на один сервер** (проще всего) или на разные.

## Шаг 1. Подключитесь к серверу

Откройте терминал (на Windows — PowerShell, на Mac — Терминал) и введите,
подставив IP своего сервера:

```bash
ssh root@IP_ВАШЕГО_СЕРВЕРА
```

Введите пароль (при вводе символы не отображаются — это нормально) и нажмите Enter.

Обновите систему:

```bash
apt update && apt upgrade -y
```

## Шаг 2. Установите 3x-ui (пропустите, если уже стоит)

```bash
bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)
```

В конце установщик покажет **адрес панели, логин и пароль**. Если не успели
записать — команда `x-ui` откроет меню, где есть пункт «Показать настройки».

> ⚠️ Нужна версия **3.0 или новее**. Проверить: пункт «Check version» в меню `x-ui`.
> Если стоит старая — обновите её тем же меню.

Откройте адрес 3x-ui в браузере и войдите. Он выглядит примерно так:
`http://IP:2053/AbCdEf/` — обратите внимание на **секретный путь в конце**
(`/AbCdEf/`), он понадобится дальше.

## Шаг 3. Подготовьте 3x-ui к работе с ботом

Нужно сделать три вещи в веб-интерфейсе 3x-ui.

### 3.1. Создайте API-токен

**Настройки → Безопасность → API Token** → создайте токен и **скопируйте**
(потом он целиком не показывается).

### 3.2. Включите подписки

**Настройки → Подписка** → включите **Subscription Service** и сохраните.
Именно по этой ссылке клиент добавляет VPN в приложение. Без неё бот не сможет
выдавать пользователям ссылки.

Если у подписки нужен свой домен или порт — укажите их в полях адреса
подписки (URI). Бот берёт адрес подписки именно оттуда.

### 3.3. Создайте хотя бы один инбаунд

**Инбаунды → Добавить** и настройте нужный протокол (VLESS Reality и т. п.).
В боте к тарифам привязываются именно **инбаунды**: сколько их выберете у
тарифа — столько подключений получит клиент.

После изменений 3x-ui может попросить перезапустить Xray / панель — согласитесь.

## Шаг 4. Скачайте и установите панель

Нужен `git`:

```bash
apt install -y git
```

Скачайте панель и запустите установщик:

```bash
git clone https://github.com/valentinvelnesev-alt/vpn-panel vpn-panel
cd vpn-panel
bash install.sh
```

Установщик сам поставит Docker, сгенерирует пароли и запустит панель. Он
задаст вопросы:

1. **С какой VPN-панелью будет работать бот?** — введите `2` (3x-ui).
2. **Как открывать панель?**
   - `1` — по домену с HTTPS (рекомендуется). Нужен домен, у которого A-запись
     указывает на IP этого сервера. Введёте домен (например `panel.example.com`)
     и e-mail для сертификата. Дальше установщик спросит, **чем обслуживать HTTPS**:
     - `1` — **Caddy (рекомендуем)**, просто нажмите Enter. Сам получает сертификат.
       Занимает порты 80 и 443.
     - `2` — **Nginx**, если на сервере уже стоит Nginx с другими сайтами.
       См. [«Если на сервере уже есть Nginx»](#если-на-сервере-уже-есть-nginx) ниже.
   - `2` — по IP без шифрования. Порт можно оставить по умолчанию (Enter → 4250).
3. **Логин и пароль администратора панели** — придумайте логин и пароль
   **не короче 12 символов**. Это вход в вашу панель, не в 3x-ui.

Через 1–2 минуты появится зелёная надпись «Готово» и **ссылка на панель**:

```
Панель:  https://panel.example.com/a1b2c3d4e5f6
```

> ⚠️ **Сохраните ссылку целиком, включая хвост** (`/a1b2c3d4e5f6`). Это секретный
> путь: без него сервер отвечает пустой страницей 404. Если потеряли:
> ```bash
> cd ~/vpn-panel && grep PANEL_SECRET_PATH .env
> ```

> 💡 **Домен и порт 443.** В режиме с доменом панель занимает порты 80 и 443.
> Если на этом же сервере ваши инбаунды 3x-ui висят на 443 — будет конфликт.
> Перенесите инбаунды на другой порт, выберите режим «по IP» или вариант с Nginx
> (он порты 80/443 не занимает — их держит ваш Nginx).

### Если на сервере уже есть Nginx

Вариант для серверов, где уже работают другие сайты на Nginx. Ваши сайты
**не затрагиваются**: установщик добавляет один отдельный файл только для
домена панели (`/etc/nginx/sites-available/vpn-panel.conf`) и не меняет
остальные конфиги.

Что нужно заранее:
- домен панели (например `panel.example.com`) с A-записью на IP сервера;
- установленный Nginx (`nginx -v` должен показать версию).

Как ставить: те же команды шага 4, а на вопросах выбрать:
домен → введите домен и e-mail → **«Чем обслуживать HTTPS?» → `2` (Nginx)**.
Если на сервере заняты порты 80/443, установщик сам предложит этот вариант по умолчанию.

Установщик сам:
1. запустит панель в Docker на `127.0.0.1:4250` (снаружи этот порт не виден);
2. создаст конфиг Nginx для вашего домена и перезагрузит Nginx (`nginx -t` проверяется до перезагрузки);
3. выпустит сертификат Let's Encrypt через `certbot` (поставит его, если нет).

Проверить, что другие сайты живы, можно командой `nginx -t` и обычным
открытием их в браузере.

**Если сертификат не выпустился** (чаще всего — A-запись ещё не обновилась),
панель не откроется по HTTPS. Когда запись обновится:

```bash
certbot --nginx -d panel.example.com -m ваш@email.com --agree-tos --redirect
```

**Нужно настроить Nginx вручную** (например, сертификат у вас уже есть)?
Вставьте в свой конфиг:

```nginx
server {
    listen 443 ssl;
    server_name panel.example.com;
    # ssl_certificate и ssl_certificate_key — ваши

    client_max_body_size 200m;

    location / {
        proxy_pass http://127.0.0.1:4250;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;  # нужен map, см. ниже
        proxy_read_timeout 300s;
    }
}
```

В блок `http { … }` (или рядом с `server`) добавьте, если такого `map` ещё нет:

```nginx
map $http_upgrade $connection_upgrade { default upgrade; '' close; }
```

После правок: `nginx -t && systemctl reload nginx`.

## Шаг 5. Подключите панель к 3x-ui

1. Откройте ссылку из шага 4 и войдите логином/паролем администратора.
2. **Настройки → Подключение к 3x-ui.**
3. Заполните:
   - **Адрес панели 3x-ui** — тот самый адрес, по которому вы открываете
     3x-ui, **вместе с секретным путём**, например `https://vpn.example.com:2053/AbCdEf`.
     Окончание `/panel...` не страшно — оно обрежется само.
   - **Токен** — API-токен из шага 3.1.
   - **Проверять TLS-сертификат** — снимите галочку, только если у 3x-ui
     самоподписанный сертификат (адрес `https://IP:порт`).
4. Нажмите **«Проверить»**. Должно появиться сообщение, что подключение
   успешно. Затем **«Сохранить»**.

Если ошибка:

| Сообщение | Что делать |
|---|---|
| «отклонила токен» | токен скопирован не целиком или создан не в той 3x-ui — создайте новый |
| «API не найден по этому адресу» | в адресе нет секретного пути 3x-ui, либо версия 3x-ui ниже 3.0 |
| «не JSON — вероятно, страница входа» | неверный адрес или токен |
| «Не удалось связаться» | порт 3x-ui закрыт файрволом или адрес указан неверно |

## Шаг 6. Подключите Telegram-бота

1. Во вкладке **Бот** вставьте токен от [@BotFather](https://t.me/BotFather).
2. В разделе тарифов выберите **инбаунды 3x-ui**, которые получит клиент.
3. Если нужен пробный период — отметьте инбаунды для триала.
4. Нажмите **«Запустить»**.
5. Напишите своему боту в Telegram `/start` — он должен ответить.

Платёжные системы подключаются на вкладке **Платежи** (адреса вебхуков
панель показывает сама).

**Проверка, что всё работает:** оформите в боте пробную подписку, получите
ссылку и добавьте её в любое VPN-приложение (v2rayNG, Hiddify, Streisand и т. д.). В
3x-ui в «Клиентах» должен появиться новый клиент.

## Обновление

```bash
cd ~/vpn-panel
curl -fsSL https://raw.githubusercontent.com/valentinvelnesev-alt/vpn-panel/main/update.sh -o update.sh
bash update.sh
```

Скрипт сам сделает бэкап базы и `.env`.

## Полезные команды

Все выполняются в папке `~/vpn-panel`.

```bash
docker compose ps               # что запущено
docker compose logs -f          # логи в реальном времени (выход: Ctrl+C)
docker compose logs panel-api   # логи только панели
docker compose restart          # перезапуск
docker compose down             # остановка
docker compose up -d            # запуск
```

## Важно: бэкап

Файл `~/vpn-panel/.env` содержит пароль базы и ключ шифрования. **Без него
данные не восстановить.** Скопируйте его к себе на компьютер и храните отдельно:

```bash
scp root@IP_СЕРВЕРА:~/vpn-panel/.env ./vpn-panel-env-backup
```

## Частые вопросы

**Можно ли потом сменить Remnawave ↔ 3x-ui?** Это переезд, а не переключатель:
уже выданные ключи останутся в старой панели. Выбирайте сразу.

**Поставил без домена, появился домен — что делать?** Запустите `bash install.sh`
заново и выберите режим 1. Данные сохранятся.

**Забыл пароль администратора.** Создайте нового администратора командой:

```bash
cd ~/vpn-panel
ADMIN_LOGIN=новый_логин ADMIN_PASSWORD='новый_пароль_от_12_символов' \
  docker compose exec -T -e ADMIN_LOGIN -e ADMIN_PASSWORD panel-api python -m app.cli create-admin
```

**Бот не отвечает.** Посмотрите `docker compose logs bot`, проверьте токен
на вкладке «Бот» и что бот запущен.
